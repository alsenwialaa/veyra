# Provider route and readiness design

Google Gemini is the default provider family, behind a provider-independent adapter. The machine-readable design manifest is `../config/contracts/provider-route-manifest.yaml`.

Current official-source review dated 2026-08-25 rechecked the `steps`-based Gemini Interactions contract, `store=false` behavior, candidate `v1beta/interactions` endpoint, and exact stable candidate model ID `gemini-3.7-flash`. These observed values are recorded centrally as **Proposed, Unconfigured, and uncertified** inputs only. The release-selected exact model ID remains `null`; endpoint/region approval, provider retention/deletion policy, credentials, budgets, fallback, capability results, and evaluation remain unset. No readiness or compatibility is claimed.

The only route is a draft with readiness **Unconfigured**, customer transmission disabled, and no fallback. Activation cannot call Gemini or transmit customer data. Saving credentials is not publication. An authorized administrator must approve privacy configuration, save a protected credential reference, select an exact release-manifest model ID after current-doc verification, and explicitly run readiness through the same adapter/contract path as runtime.

The readiness test must verify credentials, endpoint/region, exact model availability, structured output, function calling, required modalities, timeout/cancellation, malformed response and safe-error mapping, privacy settings, usage/latency, and adapter normalization without returning secrets. `Ready` also requires route-specific scenario and quality evidence; a connection-only success is insufficient.

Candidate `0.1.7` accepts only strict current `steps` responses, rejects legacy aliases, redacts prohibited outbound values before attestation, and sends only recursively closed registered ToolResult projections into response/verification phases. Catalog, knowledge, and recommendation projections were closed further, and provider continuations can be constructed only from a validated provider-safe projection. A failed readiness result preserves its actual provider error and cannot claim credentials, structured output, or text capability; non-readiness native Gemini calls are rejected. Coverage, live provider behavior, evaluation, and privacy acceptance remain incomplete, so all independent route certifications remain false.

Provider/model changes cannot alter actor scope, tool contracts, WooCommerce authority, confirmation, historical rendering, or domain semantics. A missing/invalid/deprecated/unhealthy route makes affected AI capabilities Blocked or activates only an explicitly published, disclosed, independently qualified Degraded route. It never activates hidden semantic regex/keyword/canned/fixed dialogue.
